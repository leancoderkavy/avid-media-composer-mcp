## Native Avid workflows

Guarded Comments set/clear has successful native and saved-bin evidence. A later write was rejected as `Column is not modifiable.` despite a writable declaration and successful preview; readback and saved hashes confirmed no change. A deliberate fixture close/reopen followed by a fresh write succeeded, and computer use observed the full populated Comments value. The rejection's cause and general repeatability remain unresolved; see [native Comments evidence and limits](NATIVE_CLIP_COMMENTS.md). The adapter does not automatically retry writes or close arbitrary bins to recover.

`avid_native_read` also supports `bin_columns`, preserving scoped Avid column declarations and flags. Actual fresh managed-package reads across two MCP processes returned 179 declarations matching direct native reads with unchanged bin/entry hashes. This does not authorize arbitrary metadata writes or custom-column creation. See [column discovery](NATIVE_BIN_COLUMNS.md).

`avid_native_read` supports `open_bins`, returning bounded canonical paths within the current authorized project with project checks around enumeration. Empty viewer inventories are valid; they cannot verify `show_clip` success. A fresh managed installation passed actual Sonoma open-bin, track and viewer reads plus independent saved-timeline/source hash checks (`installed-native-1a359ca7-bf96-48c0-947a-be5274da8408`). This uses the existing qualified Windows host and checkout Python oracle, not a clean machine or named AI-client GUI.

The independent Windows adapter extracts protocol descriptors locally from the checksum-qualified Media Composer 2024.12 binary. It distributes neither private SDK binaries nor extracted descriptor payloads. Native calls verify the loopback listener owner. Preview/apply uses expiring single-use tokens, scoped project/bin/source state and a per-user lock.

Native rename accepts printable ASCII punctuation/spaces within 120 characters, rejecting blank names and controls. A live multilingual probe preserved `Café` but replaced Chinese characters with question marks; exact readback rejected the result and an explicit operation restored the original name. Non-ASCII new names are therefore refused on this qualified build rather than risking lossy writes. Existing names can still be matched exactly for restoration.

`rename_clip` changes only the Name column, requiring `bin`, `mobId`, `expectedName` and a bounded new `name`. Preview and apply both check the current name; apply requires edit authority and verifies Name readback, reporting `renameVerified` separately from persistence. Actual MCP temporarily renamed the disposable Sonoma sequence and explicitly restored its original name with unchanged source media. Evidence: `native-rename-88f3ecac-a835-4c28-852c-5334cbbb4f1c`. A subsequent --persist run saved and reopened both the temporary and restored names; independent saved-bin parsing preserved the 120-frame sequence and all three media-track source ranges (native-rename-edf54b93-0b28-4568-ab5a-43c635d99f58). This qualifies that disposable sequence on this host, not arbitrary metadata writes, application restart or atomic undo.

`avid_native_read` also accepts `query: "viewers"` with a bin. It returns loaded viewer MOB IDs, viewer type, current frame and timecode only for IDs enumerated in that bin; `outOfBinOmitted` counts filtered entries without disclosing them. These are Avid-reported positions, not source-time mappings, playback verification or an atomic snapshot of concurrent editor activity. Defaults come from the qualified protobuf schema.

`avid_native_read` accepts `query: "tracks"` with `bin` and `mobId`. It checks current project scope and bin membership before `GetMobTrackInfo`. Actual Sonoma MCP reads returned V1/A1/A2 with two segments each, matching saved-bin counts, plus a timecode track. Results expose native labels, selection/monitoring/enabled flags and segment counts; they do not expose clip source ranges or a complete live graph. Track responses materialize protobuf defaults from the qualified schema, including picture type, false flags, zero segment count and unspecified audio format. These are protocol defaults, not inferred track names or independently verified editor state. Evidence: `native-refresh-dafade78-9795-4e3c-b6c5-7fa3c57d4ecf`.

Implemented actions include bin creation/open/close, media linking, marker changes, source-viewer loading, bounded all-track 30 fps subclips, [source-master AAF export](NATIVE_AAF_EXPORT.md), [AAF selects import](NATIVE_AAF_IMPORT.md) and [H.264 1080p30 export](NATIVE_EXPORT.md).
